# Omniverse Arsenal

Open-source building blocks for shipping digital products.

Omniverse is a curated repository of free and open-source software we can reuse, combine, adapt, self-host, or build on top of.

The goal is not to collect random GitHub links.

The goal is to answer:

> What can we build, and which existing open-source pieces get us there fastest?

## Rules

Every entry is reviewed for:

- Open-source or clearly reusable licensing
- Commercial-use suitability
- Self-hostability where practical
- Real functionality, not just screenshots
- Active or historically credible maintenance
- Clear product-building value

MIT is preferred. Permissive licenses such as BSD and Apache-2.0 are also eligible.

Copyleft, source-available, fair-code, or unclear licensing is kept out of the core catalogue unless explicitly marked for review.

## Arsenal map

- `arsenal/saas` SaaS foundations
- `arsenal/backend` backends and APIs
- `arsenal/ui` UI systems and components
- `arsenal/forms` forms and validation
- `arsenal/cms` CMS and content systems
- `arsenal/commerce` ecommerce engines
- `arsenal/analytics` analytics and product intelligence
- `arsenal/workflows` automation and workflow engines
- `arsenal/extensions` browser extensions
- `arsenal/pwa` installable web apps
- `arsenal/ai` AI application foundations
- `arsenal/data` database and data utilities

## Product recipes

The `recipes/` directory turns components into product architectures.

Examples:

- Lead capture system
- CRM
- Customer portal
- Booking platform
- Quotation system
- AI SaaS
- Business directory
- Ecommerce platform
- Internal operations tool
- Browser extension SaaS
- PWA field-service app

## Registry

The machine-readable catalogue lives in:

`registry/repos.json`

Each entry records:

- Repository
- License
- Category
- Type
- Stack
- What it provides
- What it can build
- Whether it composes with other Arsenal pieces
- Commercial-use notes
- Current verification date

## Core principle

Do not rebuild infrastructure because it is fun.

Reuse the boring parts.

Spend our engineering time on the part customers actually pay for: the workflow, business logic, integrations, distribution, UX, data model, and operational advantage.
